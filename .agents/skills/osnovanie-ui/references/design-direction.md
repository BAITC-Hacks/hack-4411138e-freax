# Дизайн «Основание»

Это согласованное направление для следующей работы над UI, а не описание уже внедрённого редизайна. Текущие результаты анализа и ограничения приложения остаются источником правды.

## Визуальное направление

Спокойное рабочее пространство с выразительным акцентом: светлые поверхности документов, тёмный текст, синий основной цвет и небольшой лаймовый акцент из референса Vibey. Большая типографика подходит заголовку, но не длинным цитатам. Фон документа всегда обеспечивает высокий контраст. Не смешивать разные стили из каталога в каждом блоке.

Предлагаемые токены для будущей реализации:

| Назначение | Значение |
|---|---|
| Фон рабочего пространства | `#F5F7FA` |
| Поверхность документа | `#FFFFFF` |
| Основной текст | `#172033` |
| Вторичный текст | `#536176` |
| Основной акцент / фокус | `#2454D8` |
| Лаймовый декоративный акцент | `#D9F36C`, с тёмным текстом |
| Граница | `#DCE2EA` |
| Успешный статус | `#166534` на `#ECFDF3` |
| Требует проверки | `#92400E` на `#FFFBEB` |
| Ошибка | `#B91C1C` на `#FEF2F2` |
| Шаг отступов | 4 / 8 / 12 / 16 / 24 / 32 px |
| Скругления | 10 px у полей; 16 px у крупных панелей |
| Текст интерфейса / цитат | 14–16 px; межстрочный интервал цитат 1.6 |
| Шрифт | существующий системный стек с кириллицей |
| Анимация | 120–180 ms для состояния; учитывать reduced motion |

Сначала внедрить общие CSS-переменные в подходящем существующем файле. Проверять контраст реальных сочетаний. Не использовать лайм как мелкий текст на белом.

## Структура экрана

1. Компактная шапка: название, реальный режим анализа, настройки модели.
2. Две равные карточки файлов «До» и «После». Видны имя, размер, формат и ошибка. Реальная загрузка важнее декоративного drag-and-drop; не обещать перетаскивание до его реализации.
3. Одна основная кнопка сравнения; загрузка примеров — вторичное действие. Состояние обработки не выдаёт выдуманные проценты.
4. Результаты: реальные количества кандидатов по типам, фильтр, таблица с источниками обеих версий и оценкой аналитика.
5. Просмотр доказательства: документ, пункт/ID, точная выдержка, соседний контекст. Можно адаптировать текущий dialog в широкую панель, сохранив фокус и закрытие с клавиатуры.
6. Краткое заключение и экспорт с текущими статусами проверки.

Приоритет в пятичасовом хакатоне: upload → таблица → доказательства → ошибки и адаптивность. Дополнительную навигацию, граф оргструктуры и анимации делать только при работающем основном сценарии.

## Передача между участниками

- Владелец UI правит разметку и стили; владелец интеграции — привязку состояний/API; ML — смысл находок и источников.
- При изменении `analysis.js` или общих полей заранее согласовать границу изменений. Делать небольшие коммиты; не форматировать соседние модули без необходимости.
- Обновления UI не должны скрывать резервный режим или неполноту анализа ради красивого демо.
