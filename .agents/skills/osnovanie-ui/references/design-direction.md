# Дизайн «Основание»

Реализованное направление по референсу пользователя — тёмное рабочее место с двумя панелями документов, похожее по взаимодействию на просмотр изменений в Codex. Используется собственный HTML/CSS/JavaScript; исходники компонентов 21st.dev не копировались.

## Токены и поверхности

- Фон: `#111315`; панели: `#191c1f`; поднятая поверхность: `#202428`.
- Основной текст: `#e7e9ec`; вторичный: `#9ba4ae`; граница: `#30353b`.
- Основной акцент: `#c6eb8c`, с тёмным текстом на кнопке.
- Шрифт системный, с кириллицей. Текст документов пропорциональный; ID абзацев моноширинные.
- Скругления 6–10 px, короткие переходы 160–200 ms. Учитывать prefers-reduced-motion.
- Стили изолированы в analyze.css; практикум не должен меняться вслед за рабочим местом.

## Поведение

Загрузка двух DOCX → список кандидатов → выбор замечания → две панели источников → оценка и комментарий → экспорт. После анализа загрузка сворачивается. Каждый просмотрщик независимо выбирает один из загруженных документов с указанием редакции. Анализ остаётся направленным «до / после», перестановка панелей не меняет API-контракт.

Панель слева содержит поиск, тип и фильтр непроверенных. Документы занимают основную часть экрана; ширина регулируется мышью или клавиатурой. Инспектор под документами показывает объяснение, ссылки, решение и комментарий. На телефоне блоки идут вертикально.

Подсветка обозначает тип кандидата: потеря красным, добавление зелёным, передача синим, дублирование/противоречие янтарным, сохранённое нейтрально. Всегда дублировать значение текстом. Подсветка абзаца не является посимвольным diff и не означает автоматического подтверждения.

Отсутствие источника явно обозначается. Совпадающий номер раздела можно открыть для ручного сопоставления, но нельзя превращать его в доказательство. AI/rules/fallback, реальные счётчики, ограничения и ошибки всегда видимы. Нет фиктивного confidence или выдуманных результатов.

## Передача между участниками

UI: analyze.html / analyze.css. Состояния: analysis.js. Контракт бэкенда остаётся совместимым. Перед новым изменением проверить актуальную ветку команды. Живой вызов модели проверяется отдельно от UI и тестов с имитацией ответа.
