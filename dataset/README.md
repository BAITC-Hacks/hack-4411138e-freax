# Датасет

Материалы для проверки прототипа, отобранные из `osnovanie_all_materials.zip` (Telegram, получен 2026-09-23) и скопированные сюда с проверкой SHA-256. Дополняют `sources/`, не заменяют его.

## Что уже используется приложением (не входит в этот каталог)

`sources/` — два реальных DOCX редакций 8 и 9, загружаются кнопкой «Открыть редакции 8 и 9» в `index.html`. Ручной эталон по ним уже есть: `docs/research/function-gold-set.md` (15 сопоставленных функций) и `docs/research/verification-candidates.md` (3 спорные гипотезы). Это основной трек проверки; каталог `dataset/` его не дублирует.

## `synthetic_orgdiff_ru/`

10 синтетических сценариев (C001–C010) для вымышленной «АО Учебная сеть». В каждом — 4 документа: `org`/`functions` × `before`/`after`, формат PDF (по странице, извлекаемый текст) с параллельным JSON-представлением тех же абзацев по `clause`/`id`. Эталонные выводы с источниками — `annotations/expected_results.json`; mock-ответ для фронтенда — `frontend/mock_analysis_C010.json`. После копирования пересчитаны и сверены все 80 SHA-256 из `checksums.json` — расхождений нет.

Сценарии: C001 без изменений, C002 переименование/перенумерация, C003 передача функции, C004 потенциальная потеря, C005 дублирование ответственности, C006 самопроверка закупок (конфликт интересов, запрет в п. 2.6), C007 разделение подразделения, C008 похожие функции с разными объектами (контроль ложных срабатываний), C009 неполный комплект «после» (контроль «недостаточно данных»), C010 смешанный демонстрационный набор.

**Зачем именно это.** `docs/research/llm-evaluation.md` прямо фиксирует: успех на редакциях 8/9 не доказывает готовность к скрытому комплекту жюри — нужен независимый набор с известными ответами и отдельная проверка. Пункт 11 приложенного ТЗ («Простая проверка решения») описывает ровно такую проверку: комплект, где заранее известны реорганизация, потеря функции и дублирование, и оценивается, нашёл ли агент эти случаи с корректными источниками. C004/C005/C006/C007 — это и есть такие случаи, C001/C008/C009 — контроль ложных срабатываний.

**Лицензия.** `REUSE.md` внутри каталога прямо разрешает адаптировать и включать синтетические примеры в репозиторий при сохранении пометки synthetic.

**Ограничение, которое не стоит замалчивать.** Текущий `analyzer.py`/`server.py` принимает только DOCX (см. README.md, «Ограничения MVP»); этот набор — PDF, через интерфейс сегодня не загрузится. Уже сейчас он пригоден для: ручной проверки промпта на коротких контролируемых примерах, образца формата вывода с источниками (`fragment_id`, `clause`, `quote` — та же логика адресации, что и в `analyzer.py`), и как заготовка под п. 11 ТЗ для демонстрации жюри. Чтобы прогнать через живое приложение, нужно либо научить анализатор читать PDF, либо сконвертировать 40 PDF в DOCX для теста — ни то, ни другое я не делал, чтобы не менять анализатор без запроса. Могу сделать любое из двух отдельным шагом.

## `real_sources/`

Два реально скачанных PDF годовых отчётов Казахтелекома: `original_pdfs/risk_2021.pdf` (6 стр., раздел «Система управления рисками») и `original_pdfs/report_2022.pdf` (189 стр.; нужный раздел про риски и внутренний контроль — стр. 121). Для опционального сравнения с практикой другого оператора (п. 8.2 ТЗ — опционально, не must have). Подробности и оговорки — в `real_sources/DOWNLOAD_STATUS.md` и `real_sources/LINKS_RU.md`: это публичные корпоративные отчёты, а не размеченный комплект положений; юридическая реорганизация и потеря функций ими не доказываются, а свободная лицензия на переиздание не подтверждена — использовать только для локальной проверки, не для повторной публикации.
