# Датасет

Материалы для проверки прототипа, отобранные из `osnovanie_all_materials.zip` (Telegram, получен 2026-09-23) и скопированные сюда с проверкой SHA-256. Дополняют `sources/`, не заменяют его.

## Реальные редакции 8 и 9

В `sources/` хранятся два реальных DOCX редакций 8 и 9; их можно выбрать вручную для анализа. Одноимённые файлы в корне `dataset/` являются побайтовыми копиями этих исходников, а не дополнительными независимыми источниками. Ручной эталон: `docs/research/function-gold-set.md` (15 сопоставленных функций) и `docs/research/verification-candidates.md` (3 спорные гипотезы). Кнопка «Посмотреть пример» на основном экране загружает другой, явно синтетический пакет из восьми DOCX.

## `synthetic_orgdiff_ru/`

10 синтетических сценариев (C001–C010) для вымышленной «АО Учебная сеть». В каждом — 4 документа: `org`/`functions` × `before`/`after`, формат PDF (по странице, извлекаемый текст) с параллельным JSON-представлением тех же абзацев по `clause`/`id`. Эталонные выводы с источниками — `annotations/expected_results.json`; mock-ответ для фронтенда — `frontend/mock_analysis_C010.json`. После копирования пересчитаны и сверены все 80 SHA-256 из `checksums.json` — расхождений нет. Эти 80 входных файлов также совпадают по SHA-256 с `../osnovanie_dataset_v1/`, добавленным командой. Автотесты используют `osnovanie_dataset_v1/`; локальная копия сохранена без изменения входов и разметки. Два каталога не являются двумя независимыми наборами.

Сценарии: C001 без изменений, C002 переименование/перенумерация, C003 передача функции, C004 потенциальная потеря, C005 дублирование ответственности, C006 самопроверка закупок (конфликт интересов, запрет в п. 2.6), C007 разделение подразделения, C008 похожие функции с разными объектами (контроль ложных срабатываний), C009 неполный комплект «после» (контроль «недостаточно данных»), C010 смешанный демонстрационный набор.

**Зачем именно это.** `docs/research/llm-evaluation.md` прямо фиксирует: успех на редакциях 8/9 не доказывает готовность к скрытому комплекту жюри — нужен независимый набор с известными ответами и отдельная проверка. Пункт 11 приложенного ТЗ («Простая проверка решения») описывает ровно такую проверку: комплект, где заранее известны реорганизация, потеря функции и дублирование, и оценивается, нашёл ли агент эти случаи с корректными источниками. C004/C005/C006/C007 — это и есть такие случаи, C001/C008/C009 — контроль ложных срабатываний.

**Лицензия.** `REUSE.md` внутри каталога прямо разрешает адаптировать и включать синтетические примеры в репозиторий при сохранении пометки synthetic.

**Текущее подключение.** Основной экран и `/api/analyze` принимают DOCX. Текстовые PDF уже поддержаны отдельным серверным входом `/api/packet/read` и исследовательским API/CLI (`packets.py`, `pdf_input.py`, `scripts/run_research.py`); перед запуском установите `requirements.txt`. Сценарии C001–C010 проверяются автоматическими тестами чтения PDF и адресации источников. Полный живой семантический прогон этих сценариев не выполнен. Эталон и mock-ответ предназначены для оценки и разработки, их нельзя подмешивать к документам рабочего анализа.

## `real_sources/`

Локально сохранены два PDF годовых отчётов Казахтелекома; каталог `original_pdfs/` исключён из Git и отсутствует в свежем клоне. Адреса скачивания приведены в `DOWNLOAD_STATUS.md`. Файлы: `original_pdfs/risk_2021.pdf` (6 стр., раздел «Система управления рисками») и `original_pdfs/report_2022.pdf` (189 стр.; нужный раздел про риски и внутренний контроль — стр. 121). Для опционального сравнения с практикой другого оператора (п. 8.2 ТЗ — опционально, не must have). Подробности и оговорки — в `real_sources/DOWNLOAD_STATUS.md` и `real_sources/LINKS_RU.md`: это публичные корпоративные отчёты, а не размеченный комплект положений; юридическая реорганизация и потеря функций ими не доказываются, а свободная лицензия на переиздание не подтверждена — использовать только для локальной проверки, не для повторной публикации.
