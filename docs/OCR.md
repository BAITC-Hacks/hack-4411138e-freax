# Локальный RapidOCR

`ocr_page(document_id, page)` остаётся отдельным инструментом управляющего агента.
Он работает с одной физической страницей PDF текущего исследования, не с путём,
придуманным моделью. Подлинность сохранённого оригинала проверяется по SHA-256.

## Когда Запускается

1. Рабочий процесс проверяет объекты выбранной страницы, включая вложенные формы.
2. Если `page_info.has_images=false`, возвращает `skipped / no_images`, без загрузки OCR-моделей.
3. Если изображения есть, RapidOCR распознаёт отрисованную страницу. В смешанной странице
   результат может включать и обычный текст, и текст изображений; в исходный текст он не сливается.
4. Возвращаются текст, строки с координатами и оценками `confidence`, номер страницы
   и сведения об изображениях/числе обычных текстовых символов.

Это адресный вызов, а не автоматический обход каждой страницы с логотипом.
`has_images=true` означает наличие растрового изображения, а не гарантированное наличие
полезного текста. Векторная схема без растровых изображений этим условием не распознаётся.

## Распознано И Проверено

`status=success` и `recognition_status=completed` означают, что распознавание выполнено.
`review_status=unreviewed` и совместимый `verified=false` означают отсутствие проверки
текста человеком по изображению, а не поломку движка. Оценка `confidence` относится к строке
OCR, не к истинности вывода о передаче функции. Строки ниже 0,8 помечаются `low_confidence`;
это диагностический порог, не доказательство правильности остальных строк.

Результат сохраняется отдельно в `ocr_pages`; повтор возвращается с `cached=true`.
В ответе есть `ocr_id`, документ, SHA-256, страница, размер отрисовки и система координат
`render_pixels_top_left`. Это позволяет сопоставить текст с областью оригинала.

Строки с координатами становятся адресуемыми `fragment_id`: документ, физическая
страница, хеш распознавания и номер строки. В каждом фрагменте сохраняются `source=ocr`,
координаты, размеры изображения, confidence и `verified=false`. Исходный текст PDF не
заменяется. Источником хранения служит `state.json/ocr_pages`; при восстановлении
исследования OCR-фрагменты добавляются к исходному пакету с теми же ID.

Общий гибридный индекс обновляется с повторным использованием прежних векторов.
Эмбеддинги новых OCR-строк используют настроенного провайдера и могут расходовать токены.
При ошибке обновления поиск явно переключается на текстовый по всем текущим источникам;
OCR и его адреса сохраняются. Повторный вызов возвращает кеш без повторной индексации.

Перед цитированием агент вызывает `read_context` с полученным ID. Проверяется совпадение
цитаты с распознанным текстом, чтение и редакция документа. Частичное сопоставление может
ссылаться на OCR, но получает обязательное ограничение и
`evidence_validation=ocr_transcription_quotes_matched`. Проверка изображения человеком
этим не подменяется. Непрочитанные страницы и ошибки исходного извлечения сохраняются;
непроверенный OCR новой редакции не разрешает заявлять полный охват или потерю функции.

Подготовка полностью сканированного комплекта через текущий интерфейс остаётся отдельным
ограничением. Инструмент работает с сохранёнными PDF уже подготовленного исследования.

## Установка

```powershell
python -m pip install -r requirements-ocr.txt
python scripts/prepare_ocr.py
```

Используются RapidOCR 3.9.2, ONNX Runtime и PDFium. Tesseract и Poppler не требуются.
Кириллическая модель PP-OCRv5 выбрана явно; модель по умолчанию не используется
для распознавания русских обязанностей.

Три модели скачиваются подготовительной командой в `output/ocr-models` с проверкой
опубликованных SHA-256. Каталог можно задать через `AYQYN_OCR_MODEL_DIR`.
При исследовании передаются явные локальные пути: нет скачивания моделей или отправки
документа в API самим OCR-движком. Индексация распознанного текста отдельно использует
провайдера эмбеддингов. Как и остальные настройки, переменная читается из окружения процесса;
`.env` автоматически не загружается.

Ограничения сохранены: четыре страницы за исследование, до 20 секунд на вызов в рамках
оставшегося бюджета, до 12 000 символов и 200 строк на страницу. Отрисовка до 2200 пикселей
по длинной стороне. Обрезка обозначается явно. Рабочий процесс завершается при таймауте;
это не полноценная изоляция памяти для вредоносного PDF.

## Фактическая Проверка

RapidOCR установлен, модели загружены и проверены. Живой локальный сценарий
`scripts/check_rapidocr.py` прошёл на трёх синтетических входах:

- Скан без текстового слоя: найдены «контроль исполнения договоров» и
  «Юридический департамент», возвращены координаты и оценки строк.
- Смешанная страница: обе фразы из изображения найдены при наличии обычного заголовка.
- Только обычный текст: `has_images=false`, OCR пропущен.

Сырые результаты и длительности: `output/rapidocr-check/report.json` и соседние
`*.result.json`. Это проверка трёх конкретных входов, не приёмка произвольных сканов,
таблиц, казахского текста или анализа R8/R9. Платная LLM для проверки не вызывалась.

Адресуемый путь проверен отдельно четырьмя тестами: поиск → чтение → принятие точной
OCR-цитаты; восстановление и кеш; отсутствие дублей; сохранение источников при сбое
эмбеддингов; неполнота и геометрия. Движок и эмбеддинги в этих тестах заменены контролируемыми
ответами, а индекс, сохранение и валидатор используются настоящие. Общий набор: 274 теста.
