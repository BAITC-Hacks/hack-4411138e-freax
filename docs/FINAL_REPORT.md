# AYQYN: общий отчёт по MVP HackAlem

Дата: 23 сентября 2026 года. Состояние на момент остановки работ.

## Итог

**Рабочий прототип Agentic RAG реализован. Качество анализа реальных редакций 8/9 не прошло приёмку.**

Приложение загружает документы, предоставляет агенту поиск и чтение источников, сохраняет исследование и показывает выводы для проверки сотрудником. На синтетическом комплекте подтверждено изменение гипотезы после дополнительного свидетельства. На реальных документах остаются пропуски и неверное объединение функций; точные цитаты этих ошибок не устраняют.

Это демонстрируемый прототип с проверяемыми источниками, но не готовый автоматический аудитор. Успешные технические тесты не подтверждают готовность к неизвестному контрольному комплекту жюри.

## Что Сделано

| Часть | Фактическое состояние |
|---|---|
| Загрузка | Существующий экран принимает пакет из 2–20 DOCX. Текстовые PDF доступны через сервер/CLI; PDF-загрузка в основном интерфейсе не подключена. Excel и OCR не реализованы. |
| Источники | Сохраняются оригиналы, хеши, адресуемые фрагменты, пункты и связи с контекстом. Цитаты берутся из исходного текста. |
| Поиск | BM25 и эмбеддинги объединяются через RRF. Векторный индекс локальный, без отдельного сервера БД. |
| Управление | Один агент выбирает инструменты, запросы и следующие действия. Модель не заменена заранее заданной последовательностью поисков. |
| Состояние | На диске сохраняются гипотезы, свидетельства, результаты функций, открытые вопросы, охват, бюджет и фактический журнал. |
| Незавершённые сравнения | Учёт `function_work` создаётся из функций, выделенных при чтении. Сохраняет стороны, кандидатов, вопрос, следующий шаг и статус после сокращения истории. |
| Сохранение результатов | Результаты сохраняются по отдельным ID; ошибка другой записи не откатывает принятые. Закрытие работы требует соответствующего принятого результата. |
| Проверка доказательств | Код проверяет существование адреса, точность цитаты, сторону документа, чтение источника и поля контракта. Смысловая правильность не подтверждается автоматически. |
| Ограничения | Есть бюджет действий/времени, частичный результат и завершение с недостаточностью данных. Неизвестное соответствие не должно автоматически становиться доказанной потерей. |
| Интерфейс | Тот же агент подключён к существующему экрану: выполнение, находки, источники, охват, оценка сотрудника, комментарий, экспорт и открытие сохранённого результата. |

Стек сохранён: Python и vanilla HTML/CSS/JavaScript. Семь инструментов: `list_documents`, `search`, `read_context`, `update_research_state`, `get_coverage`, `submit_findings`, `request_clarification`.

Принятый `result_id` означает, что результат сохранён и прошёл контрактные проверки. Это не подтверждение правильности интерпретации. Аналогично, `completed` означает завершение выполнения, а не заключение независимого аудитора.

## Что Проверено

**239 автоматических Python-тестов прошли перед последним API-запуском.** Они проверяют соответствующие механизмы, а не качество живой модели.

Последняя итерация добавила 17 проверок учёта функций и пять регрессий двоеточия. Проверены создание задачи из прочитанной функции без поиска, сохранение по двум прочитанным сторонам, чтение найденного кандидата с контекстом, сохранение после сокращения истории, противоречия, закрытие по результату, частичная сдача и остановка по бюджету.

Отдельно исправлен дефект: содержательный пункт с действием и завершающим двоеточием больше не исключается автоматически из источников назначения. Проверяются структура и прочитанные продолжения; требование разных назначений для кандидата дублирования сохранено. Это не автоматическая смысловая проверка дублирования.

Независимое ревью кода выявило три ошибки учёта, исправленные до API: подмена функции повторным ID, закрытие по другим источникам и возможность скрыть недостаточность данных общим завершением.

Браузерная проверка сохранённого результата: настольный и мобильный экран, светлая/тёмная темы, обе стороны источников, оригинал, ручная оценка, комментарий и Markdown-экспорт. Ошибок JavaScript и горизонтального переполнения в проверенных сценариях нет. Проверка локализации: 266 ключей в трёх языках, 12 сочетаний контраста. Фронтенд в последней итерации не изменялся.

## Агентность И Поиск

В ранее выполненном живом синтетическом контроле дополнительное приложение изменило первоначальную гипотезу потери на изменение владельца функции. Поиск нашёл нужную переформулировку на первом месте при BM25=0; семантический поиск реально участвовал. Без приложения агент завершил исследование с недостаточностью данных и не объявил потерю доказанной.

Это подтверждает агентное поведение и пользу семантического поиска в конкретном случае. Не подтверждает общую полноту поиска или надёжность анализа любых документов. Подробности и реальные журналы перечислены в [отчёте Agentic RAG](research/agentic-rag-evaluation.md); его старые утверждения об отсутствии интеграции интерфейса уже не актуальны.

### Смысловой Результат

- **G10:** изменение назначения и дополнение обязанности контроля устранения недостатков оформлены и включены в итог. Не заявлено, что мониторинг впервые появился во всей организации.
- **G08:** подготовка предложений в план смешана с взаимодействием с СВК. Корректное отдельное сопоставление предыдущего прогона не воспроизведено.
- **G09:** результат частичный. Прямое утверждение о сужении исчезло, но вывод об изменении условий охвата остаётся недостаточно обоснованным.
- **G11:** отдельно не исследован; нужные старые пункты не найдены и не прочитаны в этом запуске.
- **G12:** остался вне исследованной области.

Все 50 вхождений цитат финальных находок существуют. Однако дословный владелец в цитате не доказывает, что он относится ко всем обязанностям внутри смешанной записи. Существование источников и достаточность доказательств оцениваются отдельно.

Эта оценка выполнена главным агентом по сохранённым материалам. Дополнительный независимый полный смысловой разбор последнего запуска остановлен по запросу пользователя и не объявляется завершённым. Неисследованные сохранённые функции нельзя считать проверенными только потому, что они не попали в отчёт об изменениях.

## Основные Проблемы

1. **Выделение функций:** модель может объединить разные действия и назначения в одну работу. Учёт сохраняет такую запись, но не исправляет её смысл автоматически.
2. **Неполное завершение:** агент закончил исследование, хотя оставались шесть работ в состоянии готовности к сравнению, три обращения и около 71 секунды. Причины описывают стадию, но не содержательное препятствие.
3. **Повторное чтение:** вместо адресного пункта повторно возвращались целые группы, преимущественно ради исправления цитат. Это увеличило расход контекста.
4. **Неполный охват:** исследованы части двух групп из 109. Последний запуск не проверил живой сценарий «найти кандидата → дочитать → оформить сравнение», поскольку поиска не было.
5. **Смысловые ошибки проходят контракт:** корректная ссылка и сохранённый ID не защищают от смешения функций, неверной интерпретации изменений и необоснованных ограничений охвата.
6. **Незакрытые требования:** Excel, OCR и PDF-загрузка через основной экран отсутствуют. Надёжное обнаружение всех типов изменений на неизвестном комплекте не доказано.
