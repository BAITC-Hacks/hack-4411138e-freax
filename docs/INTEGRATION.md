# Совместный запуск TeleDoc / AYQYN

Интеграционная ветка `codex/fullstack-integration` объединяет frontend `origin/main` (1de0fb4), backend snapshot (c287a1e) и backend чата (7aa675f). История объединяется merge-коммитами. Публикация, push и merge в main не выполнялись.

## Запуск

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
# Укажите модель и ключ в .env или оставьте ключ пустым для правил.
.\run.ps1
```

Открыть `http://127.0.0.1:8765/`. Корень отдаёт HTML, `/api/health` — JSON с `frontend: true`. Статика перечислена в `ayqyn/api/static.py`; `output/`, исходники Python, настройки и секреты не раздаются. Все API работают на том же origin, обход CORS не требуется. Старые импорты перенесены в пакет `ayqyn`, корневой `server.py` — точка запуска.

## Потоки данных

- Обычный DOCX-анализ: `/api/analyze`, прежние режимы `ai`, `rules`, `fallback`, ручное уточнение неоднозначных редакций. Ответ сохраняется как дело браузера и содержит серверный ID для чата.
- Исследование: `/api/packet/read` → `/api/research/prepare` → `/api/research/run` → `GET /api/research/{id}?view=workspace`. Существующий агент сам выбирает инструменты. UI показывает фактический бюджет и статус через `view=progress`, без выдуманных процентов. Поле задачи не содержит эталонных ответов.
- Для DOCX автоматическое распределение сначала использует `classifyOnly` без анализа моделью. Для PDF нужно явно указать стороны. Обычный DOCX-путь принимает 100 МБ на файл и 200 МБ суммарно; исследование — 10 МБ и 40 МБ соответственно. При смене режима размеры проверяются повторно. Настройки модели читаются из .env через run.ps1/run.sh; поле ключа в UI отсутствует.
- Ссылка `#/app/research/r-...` только читает сохранённое исследование. После перезагрузки ничего не возобновляется автоматически. Последний ID сохраняется в sessionStorage, ключи — нет.
- Новые типы исследовательских находок включены во вкладки и экспорт. Существующие владельцы показываются из ответа сервера; неизвестные не выводятся из названия документа. `budget_exhausted`, `model_error`, `index_error`, `insufficient_data` не называются полным завершением.
- Чат находится ниже результатов и использует `analysis_id`, а не клиентский ID дела. История и версия читаются при открытии. Отправка использует `client_message_id` и `expected_version`; при неопределённом сетевом результате доступна повторная доставка идентичного запроса. Во время активного хода новый вопрос блокируется. HTTP 200 polling не считается успешным ответом модели.
- Цитаты чата открываются через серверный `/source?fragment_id=...`, текст экранируется. Утверждения имеют подписи происхождения: документ, исходный анализ, пользователь, разговор. Страницы DOCX не выдумываются. Исходный анализ и оценка человека не переписываются ответом чата.
- C010 сохраняет отдельный демонстрационный адаптер. Его нельзя импортировать в живой чат. Восемь учебных DOCX проходят настоящий анализ и помечаются как синтетические.

## Границы

Локальный однопользовательский сервер без аккаунтов, облачной синхронизации или многопользовательской изоляции. В `output/` находятся документы, ответы и журналы. При смене порта браузерная история другая; без серверного снимка старое дело остаётся доступным для просмотра/экспорта, но чат недоступен. Локальные оценки аналитика и комментарии пока не передаются серверному агенту. Серверной отмены чата нет; смена страницы не означает остановку серверного хода.

Наличие точных цитат не доказывает смысловую корректность. Предыдущая оценка R8/R9 не прошла содержательную приёмку. Интеграционные проверки подтверждают связи и обработку ошибок, а не качество модели. OCR, Excel, редактирование оригиналов и автоматическое подтверждение выводов не реализованы.
