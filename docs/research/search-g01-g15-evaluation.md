# Проверка поиска G01–G15 — 23 сентября 2026

Статус: **проверка завершена**. BM25, текущие эмбеддинги и гибрид сравнены на одном фиксированном наборе; read_context проверен отдельно. После неуспешного первого подключения выполнен один успешный запрос OpenAI: 30 текстов, 1690 токенов, text-embedding-3-small, 512 измерений. Продуктовый код, модель, RRF и хранилище в этой проверке не менялись.

## Фиксированный протокол

- [30 запросов](search-g01-g15-queries.json): для каждой функции исходный текст R8 без номера пункта и один естественный пересказ. Для длинного G12 взят непрерывный исходный фрагмент о взаимодействии, чтобы уложиться в лимит 500 символов. Цифр и подсказок адресов в запросах нет. G-ID используется только локально для подсчёта, не передаётся поиску.
- [Отдельная разметка оценки](search-g01-g15-labels.json) прочитана после ранжирования. Рабочий агент не запускался, эталон в модель не передавался. Набор диагностический, по известному эталону; это не независимая проверка обобщения.
- Один и тот же запрос проверяется по всему пакету и отдельно с before/after. Фильтра по владельцу нет. Для каждого варианта 15 запросов × 2 целевые редакции = 30 проверок. Hit означает наличие хотя бы одного фрагмента нужного пункта; это не полнота источников или правильность вывода.
- Исходные документы и кеш взяты из r-c2b51c77cfe64a09a59153bb65a94c5c: 491 + 490 фрагментов. Кеш прошёл штатную проверку HybridIndex, перестроение запрещено нулевым бюджетом. Модель text-embedding-3-small, 512 измерений.
- BM25 воспроизводит формулу текущего HybridIndex.search на тех же чанках: максимум по фрагменту, только положительные оценки, те же правила разрешения равенства. Это не упрощённый DocumentStore.search. Во всех 90 сочетаниях запроса и фильтра подтверждено точное совпадение с порядком BM25 внутри штатного гибрида.
- Для dense/hybrid получен один пакет из 30 поисковых эмбеддингов с повторным использованием между фильтрами. Ранжирование выполнил штатный HybridIndex.search; внутренние порядки компонентов считываются для оценки. Ни синтетические векторы, ни подстановка векторов документов вместо запросов не используются.

## read_context

Проверено 30 адресных чтений основного пункта (15 × 2 редакции). Полный DocumentStore.read_context сопоставлен с постраничным read_context_page, который вызывается рабочим инструментом read_context; объединённые ID совпали. Эталон использован только оценщиком для выбора проверяемого адреса. Это проверка доступности, не доказательство, что агент сам найдёт и прочитает эти места.

- Все основные чтения уложились в 1 страницу(ы) ответа по 18 000 символов.
- Обязательные продолжения G04, G05, G09 и G11 возвращены полностью в обеих редакциях (8/8 составных пунктов).
- Непосредственные заголовки владельцев доступны для всех 30 основных пунктов. Для G12 владелец указан в самом тексте. Полный набор опор владельца автоматически получен в 18/30 случаях.
- Для G01–G05 и G13 возвращается вводный контекст «внутренний аудит», но определение БВА из п. 1.2 (p11) требует отдельного чтения: 12/30 случаев. Все эти адреса доступны.
- G09/R9 требует отдельно читать p167–p172; G10 — p426/R8 и p425/R9; G12 — p136/R8 и p145/R9; G15 — p74–p77/R8 и p73–p76/R9. Эти дополнительные опоры не пришли автоматически, но доступны адресным чтением. Перечень дополнительных опор ограничен выбранной разметкой; это не исчерпывающая смысловая проверка всех условий эталона.

## Воспроизведение и артефакты

```powershell
python scripts/evaluate_search_g01_g15.py
python scripts/evaluate_search_g01_g15.py --live
```

Для --live требуется действующее локальное подключение OpenAI. Ключ не записывается скриптом в файлы. Полученные векторы запросов сохраняются для повторной оценки без новых обращений; при смене запросов или модели кеш отклоняется.

[Сырые позиции, результаты контекста и SHA-256 кода/входов](../../output/search-g01-g15/results.json). Файл локальный, находится в игнорируемом output. [Скрипт](../../scripts/evaluate_search_g01_g15.py). Поле fusion_displacements перечисляет каждый случай, когда компонент попал в топ-5/10, а гибрид — нет. Эмбеддинги запросов и фактический расход сохранены отдельно в output/search-g01-g15/query-vectors.json; повторных API-вызовов для разных фильтров не было.

Перед работой проверен Git status: сохранены изменения команды. Обновление origin не удалось: Repository not found. Поэтому измерение привязано к локальным SHA-256, а не к заявлению о последнем remote commit.

Вывод: исходные формулировки находятся устойчиво, пересказы заметно сложнее. На пересказах без фильтра hybrid улучшает BM25 с 14/30 до 18/30 в топ-10, но уступает dense (19/30); с фильтром соответственно 16/30, 20/30 и 21/30. У гибрида есть конкретные потери правильных семантических кандидатов G02/G04/G10. Контекст продолжений доступен; удалённые опоры владельца и связанные пункты требуют отдельного чтения. Проверка не доказывает качество выводов рабочего агента. Модель, RRF и хранилище оставлены без изменений согласно заданию.
