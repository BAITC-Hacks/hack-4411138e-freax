# Приёмка: сохранение результатов после ошибки

23 сентября 2026. Основание: присланное независимое офлайн-воспроизведение шага 4 запуска `r-a30fd364034e4c50a5953840e45e3844`. Предыдущие результаты и сырые ответы не переписаны.

## Исправления

1. `save_checked_results` принимает независимые записи по отдельности. Атомарность действует внутри записи; ошибка соседней записи или закрытия группы не удаляет принятую функцию. Зависимые утверждения всё ещё должны самостоятельно пройти проверку доказательств.
2. Ответ `update_research_state` содержит `accepted_result_ids`, `rejected_results` с ID/полем/кодом ошибки, `task_update_errors` с ID задачи, непрочитанными/нерассмотренными пунктами и открытыми вопросами. `accepted=false, partial=true` явно означает частичный успех, а не полный откат. Интерфейс различает эти состояния.
3. Для отсутствующего доказательства владельца возвращаются доступные уже прочитанные фрагменты самого источника и его реальных предков. Чтение включает `parent_id`. Соседний заголовок не предлагается как основание. Подстановка владельца автоматически не выполняется; заголовок ещё должен действительно назначать рассматриваемую функцию.
4. Повтор принятого `result_id` с тем же содержимым не создаёт новую запись или ревизию. При сдаче точная копия сохранённой записи включается один раз с отметкой `deduplicated`; различающиеся версии получают `conflicting_result_versions`. По сходству текста, одному номеру пункта или одинаковым ключевым словам разные действия не объединяются.
5. Для дублирования нужны два отдельных `duplication_assignment` с разными источниками действия в новой редакции. Заголовок плюс обязанность выявлять дублирование не проходят этот контракт. Код не доказывает тождество операции/этапа/условий: это всё ещё задача анализа и независимой смысловой оценки.
