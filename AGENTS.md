# Работа над «Основанием»

- Читать актуальные README.md и REVIEW_HANDOFF.md перед изменениями. Сохранять существующие изменения команды; перед работой и push проверять status и обновлять remote refs. Не переписывать общую историю.
- Для дизайна, компонентов и визуальной проверки фронтенда использовать `.agents/skills/osnovanie-ui/SKILL.md`. Связанные референсы 21st.dev и направление оформления находятся внутри этого навыка.
- Исходный стек: Python и vanilla HTML/CSS/JavaScript. Само наличие React-компонента в каталоге не является причиной менять архитектуру.
- Перед добавлением зависимости проверять существующие модули, зависимости проекта и установленное рабочее окружение. Если подходящее решение уже есть, использовать его; не устанавливать дублирующую библиотеку или инструмент. Новую зависимость добавлять только при конкретной нехватке существующих возможностей, с объяснением причины и записью в зависимости проекта для воспроизводимости.
- UI должен сохранять режим AI/rules/fallback, происхождение источников, оценку аналитика и честное представление ограничений. Не подменять анализ демонстрационными данными.
- Для актуальной документации библиотек, SDK, API и CLI использовать Context7: resolve-library-id, затем query-docs по конкретному вопросу. Для обычного анализа логики и CSS это не требуется.
- MCP и личные ключи настраиваются локально у каждого участника. Секреты и OAuth-данные не коммитить. Заимствования компонентов фиксировать с лицензией и авторством.
- По просьбе пользователя сделать pull после объединения пересматривать `docs/plans/analysis-chat-backend.md` и связанный проект API `docs/api/analysis-chat-api.md` по фактическому diff: обновлять базовый коммит, выполненные этапы, зависимости, следующий шаг и журнал. Если изменений для чата нет, фиксировать это. Область этой работы — бэкенд и чат-агент; фронтенд ведёт другой участник. Само обновление плана не означает начало реализации.
