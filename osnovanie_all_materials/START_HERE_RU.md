# Все материалы проекта «Основание»

## Что внутри
1. 01_synthetic_dataset: готовый набор из 40 PDF, 40 представлений документов в JSON, 10 сценариев, 19 целевых выводов с источниками, mock-ответ для фронтенда, инструкция и контрольные суммы.
2. 02_organizer: ссылки на ТЗ, две редакции положений и шесть общих инструкций организатора. Оригинальные файлы по этим ссылкам не включены.
3. 03_real_sources: каталог реальных источников Казахтелекома, KEGOC, Транстелекома и акимата Алматы. Статус скачивания оригиналов указан в DOWNLOAD_STATUS.md.
4. 04_public_dataset: ссылка на публичную исследовательскую базу оргструктур и сведения об условиях использования.
5. 05_project_links: репозиторий команды и ссылки соревнования.

## С чего начать прямо сейчас
Для фронтенда откройте 01_synthetic_dataset/frontend/mock_analysis_C010.json.
Для живого анализа загрузите только два PDF из 01_synthetic_dataset/inputs/C010/before в «До» и два PDF из C010/after в «После».
Правильные ответы находятся отдельно в annotations/expected_results.json. Их не передавать анализатору.
Не смешивайте документы разных сценариев или компаний в один комплект. JSON рядом с PDF - та же информация, а не отдельный источник.

## План проверки на реальных данных
- Основной тест трека: редакции 8 и 9 организатора. Скачать через Google Docs; в этой сборке есть ссылки, а не копии документов.
- Дополнительная пара: риск-менеджмент Казахтелекома 2021/2022. Проверить сопоставление обязанностей двух служб с одним департаментом. Для юридического факта реорганизации нужен приказ.
- Контроль без реорганизации: экологическое управление 2022/2023. Не выдавать изменения формулировок за изменение структуры.
- Транстелеком: только опциональное сравнение структуры другого оператора.

## Что остается получить
Полный комплект распорядительных документов и приложений, положения нескольких подразделений на одну дату, ручную разметку реальных изменений, Word/Excel и сложные сканы для проверки извлечения.
Текст годового отчета не исчерпывает функции подразделения: отсутствие обязанности в отчете не доказывает ее потерю.

## Требования ТЗ из текста пользователя
Сравнить комплекты до/после; выявить сохраненные, созданные и преобразованные подразделения;
сопоставить функции; выявить потенциальную потерю, дублирование и конфликт интересов;
для существенных выводов показать документ и пункт/фрагмент; сформировать понятное заключение.
Форматы входа: Word, PDF, Excel. Выводы рекомендательные, проверяются сотрудником.
Артефакты сдачи: работающий прототип, исходники, README запуска и описание архитектуры.
Критерии: работоспособность 25, техническая реализация 25, README/воспроизводимость 25,
практическая ценность 15, развитие и оригинальность 10.
Это краткая памятка по переданному тексту, не замена оригинала ТЗ.
