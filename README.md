# Основание

Локальный прототип по кейсу HackAlem «Анализ организационной структуры и функционала»: сравнение двух DOCX, кандидаты изменений и рисков, проверяемые фрагменты, оценка аналитика и выгрузка заключения.

## Запуск

Нужен Python 3.10 или новее. Внешних Python-зависимостей нет. Фронтенд работает без сборки; выбранные Lucide-иконки включены локально с ISC-лицензией.

```powershell
python server.py --port 8765
```

Открыть http://127.0.0.1:8765/ . Если порт занят, указать другой. Сервер доступен только на этом компьютере.

1. Выбрать два DOCX или нажать «Загрузить пример: редакции 8 и 9». Кнопка загружает реальные исходники; готовые результаты не подставляются.
2. Для семантического анализа открыть «Подключение модели», указать базовый URL, имя доступной модели и ключ. Включить AI-анализ. Для OpenAI базовый URL — `https://api.openai.com/v1`; для уже установленного совместимого локального сервера — его адрес и имя установленной модели. Модель должна поддерживать Chat Completions и JSON mode.
3. Нажать «Начать анализ». Без модели выполняется только поиск по текстовым правилам. Это не равноценная замена семантическому анализу.
4. Перейти во вкладку подразделений, функций или рисков. «Показать источники» открывает две независимые панели с оригинальным текстом и соседними абзацами. Дать оценку и оставить комментарий; оригинальный DOCX можно скачать.
5. Скачать предварительное заключение в Markdown. Оно содержит все кандидаты, происхождение, статусы и дословные фрагменты.

Начальное подключение: OpenAI API, модель `gpt-4.1-mini`. Её можно изменить в настройках; выбор по умолчанию не означает, что качество анализа уже проверено. [Документация модели](https://developers.openai.com/api/docs/models/gpt-4.1-mini).

Ключ можно задать через `OPENAI_API_KEY`, модель — `OPENAI_MODEL`, базовый адрес — `OPENAI_BASE_URL` перед запуском сервера. Поле ключа в интерфейсе необязательно, если сервер уже настроен. Ключ сервера используется только для того же базового адреса. Ключи не записываются в файлы или localStorage. Параметры модели, загруженные файлы, анализ и оценки теряются после обновления страницы. Язык интерфейса и предпочтение темы сохраняются в localStorage; ключи туда не попадают.

При включённом AI текст документов отправляется выбранному провайдеру. В режиме без модели обработка локальная. Локальная модель отдельно не устанавливается и не скачивается приложением.

## Архитектура

Для совместной работы над оформлением добавлен [навык «Основание UI»](.agents/skills/osnovanie-ui/SKILL.md): [референсы 21st.dev и подключение MCP](.agents/skills/osnovanie-ui/references/21st-components.md), [направление дизайна](.agents/skills/osnovanie-ui/references/design-direction.md). В Codex можно вызвать `$osnovanie-ui`. Это инструменты разработки, они не нужны для запуска приложения.

- `analyzer.py`: чтение OOXML без выполнения макросов, идентификаторы абзацев, сохранение текста, SHA-256; текстовые кандидаты по подразделениям, исчезнувшим и сходным формулировкам.
- `llm.py`: запрос всей пары извлечённых документов, ограниченный JSON-контракт, проверка каждого идентификатора источника. Произвольные цитаты модели не используются как исходный текст.
- `server.py`: локальный HTTP-сервер, ограниченная раздача файлов, загрузки в памяти, явный резервный режим при сбое AI.
- `analysis.js`: загрузка с drag-and-drop, состояния, вкладки, фильтры, источник в drawer, проверки аналитика, заключение.
- `i18n.js`: словари ru/kk/en, Intl; `preferences.js`: тема и язык до первого отображения; `icons.js`, `vendor/lucide`: только выбранные локальные SVG-иконки.
- `analyze.css`: токены светлой/тёмной темы, glass-поверхности и адаптивность; `assets/kazakhtelecom-logo.svg`: исходный логотип пользователя без изменения цветов и пропорций.
- `index.html`, `app.js`, `cases.js`: отдельный дополнительный практикум. Один кейс из документов и два явно синтетических. Не участвует в результатах анализа загружаемых файлов.

## Что проверено в исходниках

Пункт 3.4 редакции 8 перечисляет ДНМ и ДККМ. Пункт 3.4 редакции 9 перечисляет ДИТААД, ДОА, ДНМ и ДККМ. Это изменение перечня, а не доказательство создания юридически нового подразделения или передачи конкретных функций. Дословные выдержки практикума извлечены скриптом `scripts/extract-sources.ps1`; исходные DOCX сохранены в `sources/`.

## Ограничения MVP

- Поддерживаются два DOCX, до 10 МБ каждый. PDF, Excel, OCR и внешние нормативные базы не реализованы.
- Извлекается основное тело документа, включая таблицы. Колонтитулы, комментарии, внешние вложения не анализируются. Удалённые исправления исключаются; автоматическая нумерация Word не восстанавливается. Если номер не извлечён, надёжным адресом остаётся идентификатор абзаца.
- Текстовые правила дают кандидатов и могут пропускать переформулировки или давать ложные срабатывания. Поиск названий лучше работает с явным перечнем подразделений; правила не доказывают передачу функций. Противоречие формулировок не маркируется как конфликт интересов. Семантический конфликт интересов ищет модель.
- Не более 1500 абзацев и 250 000 символов на документ для правил; AI-пара ограничена 400 000 символов сериализованного текста. Превышение лимита не скрывается обрезкой. Очень длинные абзацы сравниваются ограниченным методом.
- AI возвращает до 40 наиболее существенных предложений. Существование ссылки проверяется программно, но логическое следование вывода из источника требует человека. Автоматического подтверждения AI-выводов нет. Одинаковая находка модели и правил может присутствовать дважды и помечается методом; число кандидатов не равно числу уникальных нарушений.
- При отсутствии/сбое модели выводится явное предупреждение и кандидаты по правилам. Пустой ответ не трактуется как отсутствие риска. Тайм-аут провайдера — 120 секунд.
- Живой вызов платной или локальной модели пока не проверен: доступ к провайдеру должен быть настроен владельцем. Тесты контракта используют имитацию ответа, не доказывают качество модели на контрольном наборе жюри.
- Это локальный прототип, не многопользовательский сервис. Загруженные документы, история анализа и оценки не сохраняются между перезагрузками. Сохранить результат можно через скачивание заключения.

## Проверки

```powershell
python -m unittest discover -s tests -v
```

Тесты охватывают произвольный синтетический DOCX-контрольный комплект с добавленным подразделением, возможной потерей и дублированием, целостность ссылок, некорректные файлы, сбой AI, JSON-контракт и защиту ключа от передачи другому провайдеру.

`scripts/check-ui.cjs` — браузерный проверочный сценарий. Требует установленную библиотеку Playwright и Chrome; путь к модулю можно указать через `PLAYWRIGHT_MODULE`. Проверяет реальные редакции 8/9, открытие источника, оценку, скачивание, мобильный экран и учебный цикл. Скриншоты и результаты находятся в `output/playwright/`.

## Приоритет следующего прогона

Настроить модель и провести живой анализ редакций 8 и 9. Проверить каждый ответ по фрагментам, затем прогнать другой контрольный комплект с известными ответами. Измерить найденные и пропущенные изменения отдельно от ложных срабатываний. До этого не заявлять надёжное обнаружение всех трёх типов изменений.

## Рабочее место проверки

- Боковая навигация ведёт в новый анализ, результаты и заключение. Разделы результатов недоступны до успешного анализа.
- Загрузка: обычный выбор или перетаскивание; название, формат, локальный размер, готовность и удаление. Ограничения совпадают с API: **один DOCX до 10 МБ на каждую сторону**. Несколько файлов отклоняются целиком с объяснением, PDF/Excel не маскируются под поддержку. Обработчик принимает произвольные названия, не привязан к примерам.
- Ожидание показывает только реально известное: чтение файлов в браузере, затем обработку сервера. API не сообщает промежуточные этапы или проценты, поэтому используется неопределённый индикатор.
- Результаты: сводка по фактическим данным, вкладки подразделений / функций / рисков / заключения. Поиск по находкам и цитатам, фильтры по типу, подразделению и проверке. Имена подразделений берутся из явных находок правил; совпадение имени в источнике не считается назначением владельца функции.
- API пока не возвращает владельцев функции отдельными полями. В соответствующих колонках отображается «Владелец не указан». Передача, потеря и дублирование остаются разными типами.
- Источники открываются в правой панели (полноэкранный диалог на телефоне). Два независимых селектора документа/редакции, изменение ширины мышью или стрелками, соседний контекст, оригинальные цитаты, ID и пункт. SHA-256 есть в подсказке метаданных и заключении. Отсутствие ссылки явно обозначается. Неподтверждённая сторона не превращается в доказательство.
- Решение и комментарий аналитика входят в реальный Markdown-экспорт. Они сохраняются только в памяти вкладки, поэтому отчёт следует скачать до перезагрузки.
- Русский / қазақша / English локализуют интерфейс, ошибки, подписи, статусы и заголовки экспорта. Переключение не сбрасывает файлы, результат, фильтры и оценки. Серверные выводы сохраняются на языке ответа, цитаты не переводятся. Параметр языка не отправляется API, поскольку контракт его не поддерживает.
- Светлая, тёмная и системная темы применяются до загрузки CSS. В localStorage сохраняются только язык и тема. Логотип не перекрашивается; в обеих темах он на светлой подложке. Glass имеет плотный fallback, документы всегда на непрозрачных поверхностях.
- Шрифт: Noto Sans при наличии, затем Segoe UI / системный. Казахские символы Ә Ғ Қ Ң Ө Ұ Ү Һ І проверены в Segoe UI. Внешних запросов к шрифтам или CDN нет.

## Проверки фронтенда

```powershell
node scripts/check-frontend.cjs
python -m unittest discover -s tests -v
```

`check-frontend.cjs` проверяет 187 ключей трёх словарей и параметры сообщений, использование ключей в HTML/JS, сохранение и fallback настроек, 12 сочетаний текста/фона с контрастом не ниже 4.5:1. 29 Python-тестов включают раздачу ES-модулей и защиту allowlist.

`scripts/check-ui.cjs` обновлён для нового интерфейса: реальные DOCX, языки и темы, независимые источники, комментарий и экспорт, сохранение настроек, ширины 360/390/768/1024/1440. Для самостоятельного запуска требует Playwright и Chrome; `APP_URL` переопределяет адрес сервера. В ходе этой работы сценарии проверены через браузер Codex; CLI-сценарий обновлён и проверен синтаксически, отдельно не запускался.

Через браузер проверены также отказ неподдерживаемого формата, повреждённый DOCX → успешный повтор, длинное казахское имя, восстановление фокуса, пустой фильтр и частичный результат при недоступной локальной модели. Это не является проверкой качества живого ИИ.
