# AYQYN · freax

Локальный прототип по кейсу HackAlem «Анализ организационной структуры и функционала»: сравнение пакета из 2–20 DOCX, кандидаты изменений и рисков, проверяемые фрагменты, оценка аналитика и выгрузка заключения.

## Запуск

Нужен Python 3.10 или новее. DOCX читается стандартной библиотекой; для пакетного входа PDF установите зависимости из `requirements.txt`. Фронтенд работает без сборки; выбранные Lucide-иконки включены локально с ISC-лицензией.

```powershell
python server.py --port 8765
```

Открыть http://127.0.0.1:8765/ . Если порт занят, указать другой. Сервер доступен только на этом компьютере.

1. Загрузить одним пакетом 2–20 DOCX, включая документы до и после реорганизации, или нажать «Посмотреть пример». Учебный пакет содержит восемь явно вымышленных DOCX (структура, планирование, аналитика, аудит — до и после). Они проходят настоящий разбор и анализ; готовые результаты не подставляются. Прежние реальные редакции 8/9 остаются в `sources/`.
2. Для семантического анализа открыть «Подключение модели», указать базовый URL, имя доступной модели и ключ. Включить AI-анализ. Для OpenAI базовый URL — `https://api.openai.com/v1`; для уже установленного совместимого локального сервера — его адрес и имя установленной модели. Модель должна поддерживать Chat Completions и JSON mode.
3. Нажать «Начать анализ». Редакции определяются по явным меткам в именах и двум номерам версий/годам одного семейства. При включённом ИИ неясные документы классифицируются по титульному тексту с проверкой точной цитаты. Неразрешённые случаи требуют выбора «До»/«После» и повторного запуска. Назначение модели — предложение, его основание видно в ходе анализа. Без модели выполняется только поиск по текстовым правилам. Это не равноценная замена семантическому анализу.
4. Перейти во вкладку подразделений, функций или рисков. «Показать источники» открывает две независимые панели с оригинальным текстом и соседними абзацами. Дать оценку и оставить комментарий; оригинальный DOCX можно скачать.
5. Скачать предварительное заключение в Markdown. Оно содержит все кандидаты, происхождение, статусы и дословные фрагменты.

Начальное подключение: OpenAI API, модель `gpt-4.1-mini`. Её можно изменить в настройках; выбор по умолчанию не означает, что качество анализа уже проверено. [Документация модели](https://developers.openai.com/api/docs/models/gpt-4.1-mini).

Ключ можно задать через `OPENAI_API_KEY`, модель — `OPENAI_MODEL`, базовый адрес — `OPENAI_BASE_URL` перед запуском сервера. Поле ключа в интерфейсе необязательно, если сервер уже настроен. Ключ сервера используется только для того же базового адреса. Ключи не записываются в файлы или localStorage. Параметры модели, загруженные файлы, анализ и оценки теряются после обновления страницы. Язык интерфейса и предпочтение темы сохраняются в localStorage; ключи туда не попадают.

При включённом AI текст документов отправляется выбранному провайдеру. В режиме без модели обработка локальная. Локальная модель отдельно не устанавливается и не скачивается приложением.

## Архитектура

Актуальная реализация: [один управляющий агент с поиском, инструментами и состоянием](docs/research/agent-architecture.md) доступен через сервер и CLI. Основной экран пока использует прежний анализ. Секционные вызовы модели не являются управляющим агентом.

Для совместной работы над оформлением добавлен [навык «Основание UI»](.agents/skills/osnovanie-ui/SKILL.md): [референсы 21st.dev и подключение MCP](.agents/skills/osnovanie-ui/references/21st-components.md), [направление дизайна](.agents/skills/osnovanie-ui/references/design-direction.md). В Codex можно вызвать `$osnovanie-ui`. Это инструменты разработки, они не нужны для запуска приложения.

- `analyzer.py`: чтение OOXML без выполнения макросов, идентификаторы абзацев, сохранение текста, SHA-256; текстовые кандидаты по подразделениям, исчезнувшим и сходным формулировкам.
- `llm.py`: классификация неопределённых редакций и общий анализ двух коллекций документов, ограниченный JSON-контракт, проверка каждого идентификатора источника. Произвольные цитаты модели не используются как исходный текст.
- `batch.py`: ограниченный пакет, определение редакций, уникальные ID `dN:pM`, имя файла и SHA-256 каждого источника.
- `ayqyn.css`, `ayqyn.js`: hero, стеклянные документы, интерактивное превью, Timeline, Parallax, CloudLoader. AgentTrace в `analysis.js` показывает только события завершённого запроса сервера.
- `server.py`: локальный HTTP-сервер, ограниченная раздача файлов, загрузки в памяти, явный резервный режим при сбое AI.
- `analysis.js`: загрузка с drag-and-drop, состояния, вкладки, фильтры, источник в drawer, проверки аналитика, заключение.
- `pdf_input.py`, `packets.py`: новый серверный вход для нескольких текстовых PDF/DOCX и реестр с адресами, ролями и ошибками; `/api/packet/read`. На основной экран пока не подключён. Для PDF нужен `pypdf` из `requirements.txt`.
- `document_store.py`: адресуемые фрагменты, чтение контекста/текста страницы, существование цитат и охват чтения.
- `embeddings.py`, `hybrid_search.py`: реальные эмбеддинги, локальный проверяемый кеш и гибридный поиск. Отдельный сервер векторной БД не нужен.
- `research_state.py`, `research_tools.py`, `research_agent.py`: сохраняемое исследование, семь инструментов, модель выбирает следующие действия, ограниченный бюджет и проверка представленных выводов.
- `i18n.js`: словари ru/kk/en, Intl; `preferences.js`: тема и язык до первого отображения; `icons.js`, `vendor/lucide`: только выбранные локальные SVG-иконки.
- `analyze.css`: токены светлой/тёмной темы, glass-поверхности и адаптивность; `assets/kazakhtelecom-logo.svg`: исходный логотип пользователя без изменения цветов и пропорций.
- `index.html`, `app.js`, `cases.js`: отдельный дополнительный практикум. Один кейс из документов и два явно синтетических. Не участвует в результатах анализа загружаемых файлов.

## Что проверено в исходниках

Пункт 3.4 редакции 8 перечисляет ДНМ и ДККМ. Пункт 3.4 редакции 9 перечисляет ДИТААД, ДОА, ДНМ и ДККМ. Это изменение перечня, а не доказательство создания юридически нового подразделения или передачи конкретных функций. Дословные выдержки практикума извлечены скриптом `scripts/extract-sources.ps1`; исходные DOCX сохранены в `sources/`.

## Ограничения MVP

- Основной экран поддерживает 2–20 DOCX, до 10 МБ каждый и до 20 МБ суммарно. Классификатор имён не угадывает неоднозначные случаи, включая три и более редакции одного семейства. Модель видит первые 30 абзацев, до 8 000 символов каждого документа для классификации; полный текст идёт в последующий анализ.
- Отдельный агентный серверный вход принимает до 20 PDF/DOCX и 40 МБ суммарно; текстовый PDF ограничен 200 страницами и 250 000 символами, частичные/непрочитанные страницы видны. PDF пока не подключён к основному экрану. Excel, OCR и внешние нормативные базы не реализованы.
- Извлекается основное тело документа, включая таблицы. Колонтитулы, комментарии, внешние вложения не анализируются. Удалённые исправления исключаются; автоматическая нумерация Word не восстанавливается. Если номер не извлечён, надёжным адресом остаётся идентификатор абзаца.
- Текстовые правила дают кандидатов и могут пропускать переформулировки или давать ложные срабатывания. Поиск названий лучше работает с явным перечнем подразделений; правила не доказывают передачу функций. Противоречие формулировок не маркируется как конфликт интересов. Семантический конфликт интересов ищет модель.
- Не более 1500 абзацев и 250 000 символов на каждую сторону пакета для правил; AI-пара ограничена 400 000 символов сериализованного текста. Превышение лимита не скрывается обрезкой. Очень длинные абзацы сравниваются ограниченным методом.
- AI возвращает до 40 наиболее существенных предложений. Существование ссылки проверяется программно, но логическое следование вывода из источника требует человека. Автоматического подтверждения AI-выводов нет. Одинаковая находка модели и правил может присутствовать дважды и помечается методом; число кандидатов не равно числу уникальных нарушений.
- При отсутствии/сбое модели выводится явное предупреждение и кандидаты по правилам. Пустой ответ не трактуется как отсутствие риска. Тайм-аут провайдера — 120 секунд.
- Выполнены реальные вызовы OpenAI на R8/R9. Подключение работает, но первые результаты не прошли содержательную приёмку: есть пропуски изменений и неверные выводы при существующих ссылках. Измерения и ограничения находятся в `docs/research/llm-evaluation.md`. Тесты контракта не доказывают качество модели на контрольном наборе жюри.
- Это локальный прототип, не многопользовательский сервис. Состояние интерфейса и оценки аналитика не восстанавливаются между перезагрузками. Живые AI-запросы сохраняют текст документов и ответы локально в `output/runs/`; ключи туда не записываются. Проверенное человеком заключение можно скачать отдельно.

## Проверки

### Управляющий Агент

Из окружения с `OPENAI_API_KEY`:

```powershell
python scripts/build_agent_control.py
python scripts/run_research.py --auto output/agent-control/previous.docx output/agent-control/current.docx output/agent-control/appendix.docx --model gpt-5.4 --reasoning-effort none --task "Проверь гипотезу: контроль исполнения договоров с поставщиками больше нигде не закреплён. Это предположение, а не установленный факт."
```

Это явно синтетические документы, не результаты анализа R8/R9. Поиск и выводы выполняются заново. Живой контроль и отдельные результаты проверки реальных документов описаны в [отчёте итерации](docs/research/agentic-rag-evaluation.md).

Для своих файлов используйте `--auto file1.pdf file2.docx` либо `--before old.docx --after new.docx annex.pdf`. `--prepare-only` строит индекс без запуска управляющей модели. `--max-calls` и `--max-seconds` ограничивают исследование; построение индекса учитывается отдельно. Через Chat Completions живой вызов `gpt-5.4` с инструментами прошёл с `reasoning_effort=none`; вариант `low` API отклонил.

Состояние и исходники сохраняются в `output/research/r-<id>/`: `packet.json`, `state.json`, `result.json`, `originals/`, `index/index.json` и реальные запросы/ответы в `turn-*/`. Это локальные данные, исключённые из Git. API-ключи не сохраняются. Эмбеддинги тоже передают текст провайдеру; их построение не является полностью локальной обработкой.

`--resume output/research/r-<id>` продолжает подготовленное или прерванное исследование, сохраняя расход бюджета. Завершённый результат не запускается заново; после исправления ошибки провайдера создайте новое исследование. Кеш не принимается при изменении исходников или модели эмбеддингов.

Серверные методы: `POST /api/research/prepare` (documents, mode, task, config, budget), `POST /api/research/run` (id, config), `GET /api/research/<id>`. Одновременный повторный запуск того же ID отклоняется. Новый браузерный экран пока не подключён.

### Прежний Анализ

Живые AI-запросы теперь сохраняют паспорт запуска в `output/runs/<run-id>/`: `request.json` (без заголовка авторизации), `response.raw.json`, `manifest.json`, `inputs.json` и принятые находки. Паспорт включает запрошенную/ответившую модель, длительность, причину завершения, признак усечения, хеши DOCX, git-коммит и хеши кода. Неуспешные ответы также сохраняются; отсутствие ключа не считается запуском модели. Папка `output/` исключена из Git и не раздаётся веб-сервером. В ней хранится текст загруженных документов.

Для воспроизводимого запуска из окружения с `OPENAI_API_KEY`:

```powershell
python scripts/run_analysis.py --before "sources/Положение_о_внутреннем_аудите_редакция_8_обезличено.docx" --after "sources/Положение_о_внутреннем_аудите_редакция_9_обезличено.docx"
```

Этот вызов использует текущий промпт и текущую схему, без эталонных ответов в запросе. Перед повтором проверьте `output/runs/`, чтобы не запускать уже выполненный анализ заново.

Экспериментальное сопоставление функций запускается с `--functions --model gpt-4.1 --sections 1 2 5` дополнительно к путям файлов. Оно проверяет точные цитаты и владельцев, сохраняет каждый запрос отдельно и возвращает категории изменения. Разделы 1/2/5 выбраны для диагностики открытого эталона, это не полный анализ документов. Сопоставление внутри раздела может пропустить перенос в другой раздел и новые функции без прежнего соответствия. Этот эксперимент пока не подключён к основной таблице приложения и не является готовым реестром функций.

```powershell
python -m unittest discover -s tests -v
```

Тесты охватывают произвольный синтетический DOCX-контрольный комплект с добавленным подразделением, возможной потерей и дублированием, целостность ссылок, некорректные файлы, сбой AI, JSON-контракт и защиту ключа от передачи другому провайдеру.

`scripts/check-ui.cjs` — браузерный проверочный сценарий. Требует установленную библиотеку Playwright и Chrome; путь к модулю можно указать через `PLAYWRIGHT_MODULE`. Проверяет учебный пакет из восьми DOCX, открытие источника, оценку, скачивание, мобильный экран и учебный цикл. Скриншоты и результаты находятся в `output/playwright/`.

## Приоритет следующего прогона

Добиться содержательной приёмки на редакциях 8/9 и только затем подключить экспериментальное сопоставление к интерфейсу. Проверить каждый ответ по фрагментам, затем прогнать независимый контрольный комплект. Пример закупок пользователя записан в `docs/research/control-procurement.md` как синтетический набор ожидаемых проверок, а не результат модели. Измерять найденные и пропущенные изменения отдельно от ложных срабатываний. До этого не заявлять надёжное обнаружение всех трёх типов изменений.

## Рабочее место проверки

- Боковая навигация ведёт в новый анализ, результаты и заключение. Разделы результатов недоступны до успешного анализа.
- Загрузка: обычный выбор или перетаскивание; название, формат, локальный размер, готовность и удаление. Ограничения совпадают с API: **один DOCX до 10 МБ на каждую сторону**. Несколько файлов отклоняются целиком с объяснением, PDF/Excel не маскируются под поддержку. Обработчик принимает произвольные названия, не привязан к примерам.
- Ожидание показывает только реально известное: чтение файлов в браузере, затем обработку сервера. API не сообщает промежуточные этапы или проценты, поэтому используется неопределённый индикатор.
- Результаты: сводка по фактическим данным, вкладки подразделений / функций / рисков / заключения. Поиск по находкам и цитатам, фильтры по типу, подразделению и проверке. Имена подразделений берутся из явных находок правил; совпадение имени в источнике не считается назначением владельца функции.
- Используемый экраном `/api/analyze` пока не возвращает владельцев функции отдельными полями. В соответствующих колонках отображается «Владелец не указан». Передача, потеря и дублирование остаются разными типами. Структурированные выводы отдельного агентного API ещё не подключены к экрану.
- Источники открываются в правой панели (полноэкранный диалог на телефоне). Два независимых селектора документа/редакции, изменение ширины мышью или стрелками, соседний контекст, оригинальные цитаты, ID и пункт. SHA-256 есть в подсказке метаданных и заключении. Отсутствие ссылки явно обозначается. Неподтверждённая сторона не превращается в доказательство.
- Решение и комментарий аналитика входят в реальный Markdown-экспорт. Они сохраняются только в памяти вкладки, поэтому отчёт следует скачать до перезагрузки.
- Русский / қазақша / English локализуют интерфейс, ошибки, подписи, статусы и заголовки экспорта. Переключение не сбрасывает файлы, результат, фильтры и оценки. Серверные выводы сохраняются на языке ответа, цитаты не переводятся. Параметр языка не отправляется API, поскольку контракт его не поддерживает.
- Светлая, тёмная и системная темы применяются до загрузки CSS. В localStorage сохраняются только язык и тема. Логотип не перекрашивается; в обеих темах он на светлой подложке. Glass имеет плотный fallback, документы всегда на непрозрачных поверхностях.
- Шрифт: Segoe UI / системный; моноширинный — только для небольших технических подписей. Казахские символы Ә Ғ Қ Ң Ө Ұ Ү Һ І проверены в Segoe UI. Внешних запросов к шрифтам или CDN нет.

## Проверки фронтенда

```powershell
node scripts/check-frontend.cjs
python -m unittest discover -s tests -v
```

`check-frontend.cjs` проверяет 240 ключей трёх словарей и параметры сообщений, использование ключей в HTML/JS, сохранение и fallback настроек, 12 сочетаний текста/фона с контрастом не ниже 4.5:1. 39 Python-тестов включают раздачу ES-модулей и защиту allowlist.

`scripts/check-ui.cjs` обновлён для нового интерфейса: реальные DOCX, языки и темы, независимые источники, комментарий и экспорт, сохранение настроек, ширины 360/390/768/1024/1440. Для самостоятельного запуска требует Playwright и Chrome; `APP_URL` переопределяет адрес сервера. В ходе этой работы сценарии проверены через браузер Codex; CLI-сценарий обновлён и проверен синтаксически, отдельно не запускался.

Через браузер проверены также отказ неподдерживаемого формата, повреждённый DOCX → успешный повтор, длинное казахское имя, восстановление фокуса, пустой фильтр и частичный результат при недоступной локальной модели. Это не является проверкой качества живого ИИ.


## AYQYN: визуальная система и пакет документов

Изучены исходники трёх проектов команды: KazPunct, freax_ds и freaxlab. Решения, пути компонентов и атрибуция описаны в [дизайн-реестре](docs/AYQYN_DESIGN.md). Оригинальная композиция реализована без новых зависимостей. Исходный логотип Казахтелекома сохранён. Декоративные результаты hero и превью явно обозначены как пример.

API `/api/analyze` принимает новый `documents: [{name, data, side?: "auto"|"before"|"after"}]`. Старый контракт `before`/`after` сохранён. Ответ при неоднозначности: `needs_review: true`, `documents` с классификацией; без находок. Успешный ответ сохраняет агрегаты `before`/`after` и добавляет индивидуальные `documents`, источник каждого абзаца и `trace` с реальными завершёнными этапами. Идентификаторы абзацев уникальны в пределах пакета, даже при одинаковых именах файлов. Выбор документа в каждой панели независим. Заключение включает индивидуальные SHA-256.

Прогресс во время запроса — неопределённый индикатор реальной обработки. AgentTrace раскрывает завершённый запуск, а не имитирует онлайн-события. При отсутствии подключённой модели классификация работает по именам, а анализ — по текстовым правилам. При неизвестной редакции анализ не запускается с произвольным порядком файлов.
