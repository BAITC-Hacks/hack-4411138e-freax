# AYQYN · HackAlem

Бэкенд Agentic RAG для сравнения организационных документов. Один управляющий агент ищет назначения функций, читает источники, сохраняет сопоставления и предлагает выводы для проверки сотрудником.

**Старый веб-интерфейс удалён по решению команды.** HTTP API и CLI сохранены. Для нового фронтенда: [дизайн и сценарии](docs/FRONTEND_HANDOFF.md), [контракт API](docs/API.md). Корневой адрес сервера возвращает JSON, а не HTML.

**Качество R8/R9 не принято.** Последний оценённый запуск до переноса оформил G10; G08 смешан с другой обязанностью, G09 частичный, G11/G12 пропущены. Точная цитата не гарантирует правильности вывода. [Общий отчёт](docs/FINAL_REPORT.md), [последняя оценка](docs/research/function-work-evaluation.md), [эталон](docs/research/function-gold-set.md).

## Установка и запуск

Python 3.10+. Из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py --port 8765
```

Linux/macOS: используйте `.venv/bin/python` вместо `.\.venv\Scripts\python.exe`.

`GET http://127.0.0.1:8765/api/health`:

```json
{"service":"AYQYN","status":"ok","frontend":false}
```

Сервер слушает только `127.0.0.1`. Чтение пакета, просмотр старого результата и автоматические тесты не требуют модели. Подготовка нового индекса и запуск агента могут обращаться к провайдеру.

## Подключение модели

Настройки перечислены в [.env.example](.env.example). Приложение читает **окружение процесса**: `.env` автоматически не загружается. Задайте свой `OPENAI_API_KEY` локально перед запуском; не записывайте секрет в репозиторий или документы.

```powershell
$env:OPENAI_BASE_URL = 'https://api.openai.com/v1'
$env:OPENAI_MODEL = 'gpt-5.4'
```

Ключ сервера применяется только для соответствующего базового адреса. Агенту нужны native tool calling и endpoint эмбеддингов; произвольный совместимый сервер отдельно не проверен.

Последний оценённый запуск: `gpt-5.4-2026-03-05`, `reasoning_effort=none`; эмбеддинги `text-embedding-3-small`, 512 измерений. Это проверенные настройки подключения, а не подтверждение качества анализа.

В HTTP задавайте `config.model` явно: совместимый `/api/config` пока возвращает резервный `gpt-4.1-mini`, если `OPENAI_MODEL` отсутствует. CLI по умолчанию использует `gpt-5.4`.

Текст документов отправляется выбранному провайдеру при построении эмбеддингов и анализе. Оригиналы, состояние и журналы сохраняются локально в `output/`.

## CLI: исследование комплекта

В примерах `python` — интерпретатор с установленными зависимостями:

```powershell
# Автоматическое определение редакций
python scripts/run_research.py --auto "sources/Положение_о_внутреннем_аудите_редакция_8_обезличено.docx" "sources/Положение_о_внутреннем_аудите_редакция_9_обезличено.docx" --model gpt-5.4 --reasoning-effort none --max-calls 24 --max-seconds 240

# Явное назначение сторон
python scripts/run_research.py --before "before.docx" --after "after.pdf" --model gpt-5.4 --reasoning-effort none

# Синтетический комплект; его ожидаемые ответы не подаются агенту
python scripts/run_research.py --case C010 --model gpt-5.4 --reasoning-effort none

# Возобновление с оставшимся бюджетом
python scripts/run_research.py --resume "output/research/r-<id>" --model gpt-5.4 --reasoning-effort none
```

`--prepare-only` не запускает управляющий цикл, но **может расходовать API-токены эмбеддингов**. `--reuse-index <путь/index.json>` использует только совместимый проверенный кеш, не готовые ответы. Остальные параметры — через `--help`.

Для просмотра используйте `GET /api/research/<id>` или `?view=workspace`. Не используйте CLI `--resume` просто для чтения: незавершённое исследование продолжит работу.

## Структура

```text
ayqyn/
  documents/   # DOCX/PDF, комплекты, источники, контекст
  retrieval/   # BM25, cosine, RRF, локальный индекс
  agent/       # цикл, инструменты, состояние, функции, память, метрики
  analysis/    # прежние пакетный и секционный режимы
  providers/   # обращения к LLM и эмбеддингам
  storage/     # журналы запросов и манифесты
  api/         # HTTP API и представление для фронтенда
  paths.py     # стабильный корень проекта
server.py      # совместимая точка запуска
scripts/       # CLI, подготовка примеров, диагностика
tests/
docs/
sources/
output/        # результаты и кеши; не в Git
```

[Карта модулей](docs/architecture.md). Наборы `osnovanie_dataset_v1/` и локальный `osnovanie_all_materials/` оставлены на прежних местах. Gold set и ожидаемые ответы синтетики не должны индексироваться как входные документы.

## Работа агента

1. Парсер создаёт адресуемые фрагменты и связи с контекстом; документы получают роли `before/after/common/unknown`.
2. BM25 и реальные эмбеддинги объединяются RRF. Индекс — `output/research/<id>/index/index.json`; Qdrant не используется.
3. Модель выбирает инструменты и запросы. `function_work` хранит выделенные обязанности, кандидатов и открытые вопросы.
4. Результаты сохраняются по ID; ошибки других записей их не откатывают. Проверяются точность цитат, стороны и контракт.
5. Частичный результат содержит ограничения. Смысловую правильность проверяет сотрудник.

Семь инструментов: `list_documents`, `search`, `read_context`, `update_research_state`, `get_coverage`, `submit_findings`, `request_clarification`.

## Проверки

```powershell
python -m unittest discover -s tests -q
python scripts/evaluate_search_g01_g15.py
```

Вторая команда повторяет оценку поиска без API по локальным артефактам и сохранённым векторам запросов. Они не поставляются с Git. При отсутствии кеша команда требует явный `--live`; он вызывает API. До переноса прошли 239 тестов; результат проверки новой структуры — в [REVIEW_HANDOFF.md](REVIEW_HANDOFF.md).

## Ограничения

- Агентный вход: до 20 DOCX/текстовых PDF, до 10 МБ на файл и 40 МБ на комплект. PDF: до 200 страниц и 250 000 символов. Непрочитанные области обозначаются. Excel и OCR отсутствуют.
- Извлекается основное тело DOCX, включая таблицы; колонтитулы, комментарии и внешние приложения не анализируются. Автоматическая нумерация Word полностью не восстанавливается.
- R8/R9 не прошли смысловую приёмку: смешение функций, повторные чтения, пропуски. [Поиск также имеет измеренные потери при объединении выдач](docs/research/search-g01-g15-evaluation.md).
- `checked`, `result_id` и `completed` не означают независимое подтверждение вывода. Отсутствие совпадения не доказывает потерю обязанности.
- Старый `/api/analyze` сохранён: `rules/ai/fallback`. Новый `/api/research/*` не подменяет сбой агента правилами.
- Готового frontend сейчас нет. Оценки аналитика и Markdown-экспорт раньше выполнялись в браузере; серверных endpoints сохранения оценок и экспорта пока нет.

Перенос файлов не меняет модель, промпт, поиск или смысловой результат. Следующие работы по качеству перечислены в [передаче ревьюеру](REVIEW_HANDOFF.md).
